# Analisis Kesalahan Model (Error Analysis: FP & FN)

Dokumen ini menggabungkan hasil analisis manual 20 sampel *False Positive* (`FP-01` s.d. `FP-20`) dan 20 sampel *False Negative* (`FN-01` s.d. `FN-20`) dari model terbaik kita (**Random Forest**, F1 = `0.9557` pada 10.382 data uji CSIC 2010) yang dikerjakan oleh Orang A (`01`–`07`), Orang B (`08`–`14`), dan Orang C (`15`–`20`), serta membandingkan pola kesalahan model klasik dengan LLM lokal (`llama3.2:3b`).

## 3. Ringkasan 5 Baris (Rekapitulasi Kategori & Implikasi Keamanan)

1. **Distribusi Kategori False Positive (20 sampel):** Terdiri dari **Karakter non-ASCII / pola parameter keranjang (`anadir.jsp`)** sebanyak 6 sampel (`FP-01, 05, 09, 14, 15, 16`), **Kemiripan sub-kata kunci SQL (`insertar`) & parameter numerik** sebanyak 6 sampel (`FP-02, 06, 11, 17, 18, 20`), **Karakter non-ASCII / tanda baca pada form panjang (`registro.jsp`)** sebanyak 4 sampel (`FP-03, 04, 08, 10`), **Permintaan pendek & endpoint jarang** sebanyak 3 sampel (`FP-07, 12, 13`), serta **Kombinasi password alfanumerik campuran** sebanyak 1 sampel (`FP-19`).
2. **Distribusi Kategori False Negative (20 sampel):** Terdiri dari **Karakter sisipan tunggal/ganda (`*`, `?`, `/`, `|`, `'`, `+`)** sebanyak 14 sampel (`FN-02, 03, 04, 07, 09, 10, 11, 13, 14, 15, 16, 17, 18, 20`), **Anomali panjang digit / format / nilai parameter halus (overflow & angka negatif)** sebanyak 4 sampel (`FN-05, 06, 08, 12`), dan **Manipulasi metode HTTP (`PUT` / Verb Tampering)** sebanyak 2 sampel (`FN-01, 19`).
3. **Dua Kategori Kesalahan Paling Sering (Top 2 dari 40 Sampel):** Urutan pertama adalah **Karakter sisipan tunggal/ganda (fuzzing 1-byte)** pada FN sebanyak **14 dari 40 sampel (35%)**, dan urutan kedua adalah **Karakter non-ASCII (encoding Latin-1 Spanyol `%F1/%F3/%E9`) pada parameter keranjang & form panjang** pada FP sebanyak **10 dari 40 sampel (25%)**.
4. **Akar Masalah Teknis Model Klasik:** Representasi TF-IDF n-gram karakter (2–4) dan 6 fitur buatan tangan (`panjang`, `n_karakter_khusus`, `n_persen`, `n_kata_sql`, `n_kata_script`, `n_digit`) sangat peka terhadap kepadatan encoding `%XX` (sehingga teks bahasa Spanyol beraksen sering menjadi FP) namun kurang peka terhadap mutasi satu karakter di tengah request panjang, anomali semantik angka (`cantidad=-12` atau 16–22 digit angka), serta metode HTTP `PUT`.
5. **Mengapa FN Lebih Berbahaya daripada FP bagi Bank:** Bagi institusi perbankan, **False Negative (FN)** jauh lebih berbahaya karena serangan nyata (seperti manipulasi nominal/jumlah transaksi negatif pada `FN-12`, *integer overflow* pada `FN-05`, atau *fuzzing* autentikasi) berhasil menembus sistem tanpa terdeteksi dan dapat menimbulkan kerugian finansial langsung maupun kebocoran data nasabah, sedangkan **False Positive (FP)** hanya memblokir sementara transaksi pengguna sah yang masih dapat diverifikasi ulang melalui mekanisme *challenge* (seperti CAPTCHA atau OTP).

## 4. Perbandingan Jenis Kesalahan: Model Klasik vs LLM Lokal (`llama3.2:3b`)

Berdasarkan evaluasi pada 400 sampel uji berimbang (200 normal + 200 serangan) di `reports/comparison_metrics.json` dan `reports/comparison.csv`:

| Metrik / Karakteristik | Model Klasik (`logreg` / `rf`) | LLM Lokal (`llama3.2:3b` Zero-Shot) |
| :--- | :--- | :--- |
| **Precision (Subset 400)** | `1.000` (`logreg`) | `0.492` |
| **Recall (Subset 400)** | `0.895` (`logreg`) | `0.890` |
| **F1-Score (Subset 400)** | `0.945` (`logreg`) | `0.633` |
| **Confusion Matrix (Subset 400)** | TP=`179`, FP=`0`, FN=`21`, TN=`200` | TP=`178`, FP=`184`, FN=`22`, TN=`16` |
| **Kecepatan rata-rata per request** | `< 0.001` detik (instan setelah muat model) | `2.37` detik / request (`~15.8` menit untuk 400 request) |

### Pola Perbedaan Kesalahan:
1. **Ledakan False Positive pada LLM Zero-Shot (`FP = 184` dari 200 trafik normal):**
   - Tanpa *fine-tuning* atau contoh *few-shot* khusus aplikasi `tienda1`, `llama3.2:3b` bersifat **terlalu paranoid (over-sensitive)**. Begitu melihat URL dengan banyak parameter form (`dni`, `password`, `ntc` kartu kredit di `registro.jsp`) atau encoding karakter Latin-1 (`%F3`, `%E9`, `%F1`), LLM menganggapnya sebagai percobaan injeksi atau pengiriman data mencurigakan.
   - Sebaliknya, model klasik yang dilatih langsung pada distribusi CSIC 2010 mempelajari pola normal `tienda1` dengan sangat presisi (`FP = 0` pada subset 400 untuk `logreg`, dan `Precision = 98.11%–98.94%` pada 10.382 data uji penuh).
2. **Kesamaan pada False Negative (`FN = 21` pada Klasik vs `FN = 22` pada LLM):**
   - Baik model klasik maupun LLM lokal sama-sama kesulitan mendeteksi serangan *parameter tampering* halus (seperti perubahan nilai ID/angka yang tampak wajar tanpa konteks skema database) dan mutasi karakter tunggal yang tersembunyi.
3. **Kesimpulan Praktis untuk WAF / Detektor Serangan Web:**
   - Model klasik (**Random Forest / Logistic Regression**) jauh lebih unggul untuk penyaringan lalu lintas web *real-time* karena memiliki *precision* tinggi, *false alarm* sangat rendah, dan latensi sub-milidetik.
   - LLM lokal berukuran kecil (`3B`) dalam mode *zero-shot* belum layak dipasang langsung sebagai pemutus trafik utama karena tingkat *false positive* mencapai 92% (184/200 normal diblokir) dan latensi ~2,4 detik per request.
